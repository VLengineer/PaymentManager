# Руководство по логированию в приложении "Платежный календарь БДДС"

## Обзор

В приложение добавлена система логирования для отладки и мониторинга работы. Все логи выводятся в консоль браузера (Console IDE) с временными метками и уровнями важности.

## Уровни логирования

| Уровень | Описание | Когда используется |
|---------|----------|-------------------|
| `DEBUG` | Отладочная информация | Детали запросов, проверка условий, промежуточные состояния |
| `INFO` | Информационные сообщения | Успешные операции, начало/конец важных процессов |
| `WARN` | Предупреждения | Не критичные проблемы, требующие внимания |
| `ERROR` | Ошибки | Критические ошибки, исключения, сбои операций |

## Модули с логированием

### 1. auth.js - Модуль аутентификации
**Префикс:** `[AUTH]`

**Логируемые события:**
- Попытка входа пользователя
- Отправка запроса на сервер
- Получение ответа от сервера
- Ошибки аутентификации
- Успешная аутентификация
- Сохранение токена
- Выход пользователя
- Проверка авторизации

**Пример логов:**
```
2025-01-XXTXX:XX:XX.XXXZ [AUTH] [INFO] Попытка входа для пользователя: admin
2025-01-XXTXX:XX:XX.XXXZ [AUTH] [DEBUG] Отправка запроса на /api/auth/login {method: "POST", ...}
2025-01-XXTXX:XX:XX.XXXZ [AUTH] [DEBUG] Получен ответ от сервера {status: 200, statusText: "OK", ok: true}
2025-01-XXTXX:XX:XX.XXXZ [AUTH] [INFO] Успешная аутентификация {username: "admin", role: "ADMIN"}
2025-01-XXTXX:XX:XX.XXXZ [AUTH] [DEBUG] Токен сохранен в sessionStorage
```

## Формат логов

Все логи имеют единый формат:
```
<Timestamp> <Prefix> [<Level>] <Message> [<Data>]
```

Где:
- **Timestamp**: ISO 8601 формат времени (например, `2025-01-19T14:30:00.000Z`)
- **Prefix**: Префикс модуля (`[AUTH]`, `[LOGIN]`, `[CALENDAR]`)
- **Level**: Уровень логирования (`DEBUG`, `INFO`, `WARN`, `ERROR`)
- **Message**: Человекочитаемое сообщение
- **Data**: Дополнительные данные (объекты, значения)

## Как использовать логи для отладки

### 1. Фильтрация по модулю
В консоли браузера используйте фильтр по префиксу:
- `/\[AUTH\]/` - показать только логи аутентификации
- `/\[LOGIN\]/` - показать только логи страницы входа
- `/\[CALENDAR\]/` - показать только логи календаря

### 2. Фильтрация по уровню
- Скройте DEBUG логи для уменьшения шума
- Показывайте только ERROR для поиска проблем

### 3. Поиск проблем
При ошибке 405 (Method Not Allowed):
1. Проверьте логи `[AUTH] [DEBUG]` - какой метод отправляется
2. Проверьте логи `[AUTH] [DEBUG]` - какой ответ получен от сервера
3. Сверьте с бэкендом - правильный ли URL используется

## Диагностика ошибки 405 Method Not Allowed

Ошибка 405 означает, что сервер не поддерживает указанный HTTP метод для данного endpoint.

**Возможные причины:**
1. Неправильный URL endpoint
2. Сервер не запущен или недоступен
3. CORS ограничения
4. Неправильный Content-Type

**Решение:**
1. Убедитесь, что backend запущен на порту 8000
2. Проверьте, что frontend проксирует `/api/*` на backend
3. Проверьте логи - какой статус возвращает сервер

## Добавление логирования в новые модули

Для добавления логирования в новый модуль:

1. Добавьте настройки в начало файла:
```javascript
const LOG_PREFIX = '[YOUR_MODULE]';
const LOG_LEVELS = {
    DEBUG: 'DEBUG',
    INFO: 'INFO',
    WARN: 'WARN',
    ERROR: 'ERROR'
};
```

2. Добавьте функцию log:
```javascript
function log(level, message, data = null) {
    const timestamp = new Date().toISOString();
    const logMessage = `${timestamp} ${LOG_PREFIX} [${level}] ${message}`;
    
    switch(level) {
        case LOG_LEVELS.DEBUG:
            console.log(logMessage, data !== null ? data : '');
            break;
        case LOG_LEVELS.INFO:
            console.info(logMessage, data !== null ? data : '');
            break;
        case LOG_LEVELS.WARN:
            console.warn(logMessage, data !== null ? data : '');
            break;
        case LOG_LEVELS.ERROR:
            console.error(logMessage, data !== null ? data : '');
            break;
        default:
            console.log(logMessage, data !== null ? data : '');
    }
}
```

3. Используйте log() в коде:
```javascript
log(LOG_LEVELS.INFO, 'Описание события', { дополнительные: 'данные' });
```
